# docs — 로봇웨어하우스 문서 안내

제4회 경남 AI·SW 경진대회 3-2(MetaQuest2 VR 기반 피지컬 AI Agent) 출품작 **로봇웨어하우스**의 설계·계약·테스트·UI 문서를 모아 둔 폴더입니다.
처음 보는 사람은 아래 **읽는 순서**를 따라가면 되고, 코드를 고치기 전에는 **계약 문서**(`schema.md`, `api.md`, `vr_client_api.md`)를 먼저 확인합니다.

## 폴더 구성

```
docs/
├─ README.md                 # 이 문서
├─ schema.md                 # 격자 지도 스키마 · 좌표 규칙 (공동 소유 계약)
├─ api.md                    # Unity ↔ 서버 API 명세 (공동 소유 계약)
├─ vr_client_api.md          # VR이 보내고 기대하는 REST·WebSocket (VR 구현 기준)
├─ architecture/             # 설계 문서 자리 (아래 '정리 예정' 참고)
├─ 문서_양식_모음/            # 제출물 양식, 아키텍처, 요구사항, 시나리오, 테스트, 회고
└─ ui_재료/                   # VR UI 설계 문서와 화면 예시 이미지
```

## 계약 문서 (공동 소유)

VR, 경로 엔진, Agent 서버가 함께 쓰는 약속입니다. 한쪽만 고치면 다른 쪽이 깨집니다.

| 문서 | 내용 | 코드 위치 |
|---|---|---|
| [schema.md](schema.md) | 격자 지도 필드, 좌표 규칙(격자 x,y → Unity x,0,y), 칸 유형, 바닥 색, 랙 규격·운영 규칙 | `server/schema/`, Unity `Data/GridMap.cs` |
| [api.md](api.md) | REST 경로와 WebSocket `/ws/{session_id}` 메시지, 지도 되묻기, 제품 규격·수량, 처리 못 한 주문 방침 | `server/api/` |
| [vr_client_api.md](vr_client_api.md) | VR 쪽에서 본 같은 계약. 문서에 없어 VR이 **가정**한 항목 표시, 로봇 `state` 값과 색 | Unity `Network/ApiRoutes.cs` |

**변경 절차:** ① `schema_version`을 올리고 ② 문서를 먼저 고친 뒤 ③ 팀 채널에 공지하고 ④ 서버와 Unity 코드를 같은 날 함께 고칩니다.

## 문서 추가 규칙

- **설계·테스트 문서**는 번호를 붙여 `문서_양식_모음/`에 둡니다. 판이 바뀌면 파일명 끝에 `_v2`처럼 붙이고, 예전 판은 지웁니다(이력은 git에 남습니다).
- **계약 문서**(`schema.md`, `api.md`, `vr_client_api.md`)는 위 변경 절차를 따릅니다.
- **UI 문서와 이미지**는 `ui_재료/`에 둡니다. 화면 예시는 `S번호 — 화면이름.png` 형식을 따릅니다.
- **올리지 않는 것:** 참가 신청서, 재학증명서, 서명 이미지, 메신저 대화 같은 개인정보(이 저장소는 공개 상태입니다), API 키(`.env`), 빌드 산출물(APK는 Releases에 첨부).
