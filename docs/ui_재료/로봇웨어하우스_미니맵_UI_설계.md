# 로봇 창고 사용자 UI — 미니맵 기능 설계

## 1. 제안

맵이 생성된 이후 사용자 화면의 한쪽 구석에 **미니맵(Minimap)**을 항상 표시하고, 시뮬레이션 실행 중에는 미니맵 안에서 로봇의 위치와 움직임이 실제 시뮬레이션과 동기화되어 보이도록 한다.

목적은 사용자가 3D 창고를 직접 바라보면서도 전체 창고의 구조와 로봇들의 현재 위치·이동 상황을 한눈에 파악할 수 있도록 하는 것이다.

현재 시스템의 시뮬레이션 프레임에는 `t`, `robots[{id,x,y,state}]` 형태의 로봇 위치와 상태 정보가 있으므로, 기존 데이터를 3D 화면과 미니맵이 함께 사용하는 구조를 권장한다.

---

# 2. 미니맵 기본 위치

사용자 화면의 **오른쪽 아래**를 1순위 위치로 권장한다.

```text
┌──────────────────────────────────────────────┐
│                                              │
│                  3D 창고                     │
│                                              │
│       ████       ████                        │
│       ████   🤖 → → →                       │
│                                              │
│                    🤖                        │
│                                              │
│                                              │
│                              ┌───────────┐   │
│                              │ ┌───────┐ │   │
│                              │ │ ▪  ▪  │ │   │
│                              │ │   ●   │ │   │
│                              │ │ ▪  ▪  │ │   │
│                              │ └───────┘ │   │
│                              │  MINIMAP  │   │
│                              └───────────┘   │
│                                              │
└──────────────────────────────────────────────┘
```

### 이유

- 기존 주요 조작 영역을 방해하지 않음
- 3D 공간을 보면서 전체 상황을 확인할 수 있음
- 재생 중 로봇의 움직임을 보조적으로 확인할 수 있음
- 별도의 화면 전환 없이 전체적인 상황을 파악할 수 있음

---

# 3. 미니맵 표시 상태

미니맵은 맵 생성 여부와 시뮬레이션 상태에 따라 단계적으로 정보를 표시한다.

```text
[ 맵 생성 전 ]
미니맵 없음

       ↓

[ 맵 생성 완료 ]
미니맵 표시
→ 창고 구조 표시

       ↓

[ 시뮬레이션 준비 ]
로봇 위치 표시

       ↓

[ 시뮬레이션 실행 ]
로봇 위치 실시간 이동
+ 방향 표시

       ↓

[ 일시정지 ]
현재 위치에서 정지

       ↓

[ 재생 완료 ]
최종 위치 유지
+ 결과 요약
```

---

# 4. 맵 생성 완료 상태

맵이 생성되면 미니맵이 등장하고, 먼저 **창고 구조**를 표시한다.

```text
┌───────────────────────────────┐
│                               │
│        3D WAREHOUSE           │
│                               │
│                               │
│                    ┌───────┐  │
│                    │MINIMAP│  │
│                    │       │  │
│                    │ ▪ ▪ ▪ │  │
│                    │ ▪   ▪ │  │
│                    │ ▪ ▪ ▪ │  │
│                    └───────┘  │
└───────────────────────────────┘
```

이 단계에서는 시뮬레이션 데이터가 아직 없으므로 로봇을 표시하지 않는다.

---

# 5. 시뮬레이션 준비 상태

`sim_ready` 이후에는 미니맵에 로봇 위치를 표시한다.

예를 들어 로봇이 4대라면:

```text
MINIMAP

┌───────────────┐
│ █ █ █ █ █ █ █ │
│ █ · · · · · █ │
│ █ · ● · ● · █ │
│ █ · · · · · █ │
│ █ · ● · ● · █ │
│ █ · · · · · █ │
│ █ █ █ █ █ █ █ │
└───────────────┘
```

---

# 6. 실행 중 로봇 움직임

시뮬레이션의 시간축과 미니맵의 로봇 위치를 동일하게 유지한다.

예:

```text
t = 100

● → → →


t = 101

    ● → →


t = 102

      ●
```

즉:

```text
Frame Data
    │
    ├──────────────→ 3D Robot
    │
    └──────────────→ Minimap Robot
```

3D 공간의 로봇과 미니맵의 로봇은 같은 프레임 데이터를 사용한다.

---

# 7. 로봇 상태 표시

현재 시뮬레이션 프레임에 로봇 상태가 포함되어 있으므로 미니맵에서도 상태를 표현할 수 있다.

기본적으로:

```text
● 이동
○ 대기
◆ 적재
```

와 같이 **모양 + 색상**을 함께 사용하는 것을 권장한다.

색상만으로 상태를 구분하면 접근성이 떨어질 수 있으므로 모양을 함께 사용한다.

---

# 8. 선택된 로봇 강조

미니맵에서 특정 로봇을 선택하면 해당 로봇을 강조한다.

```text
┌────────────────────┐
│      MINIMAP       │
│                    │
│  · · · · · · ·     │
│  ·  ●1 · · ●2      │
│  · · · ★ · ·       │
│  · ●3 · · · ●4     │
│                    │
└────────────────────┘
```

예:

```text
★ R1
```

선택된 로봇은 3D 공간에서도 함께 강조한다.

```text
미니맵에서 R1 클릭
       ↓
R1 선택
       ↓
3D에서 R1 강조
```

---

# 9. 미니맵에 표시할 정보

미니맵에는 다음 정보를 기본적으로 고려한다.

### 기본 표시

- 창고 구조
- 로봇 현재 위치
- 로봇 진행 방향

### 선택 시

- 선택된 로봇
- 해당 로봇 경로

### 옵션 활성화 시

- 모든 로봇 경로
- Grid
- 병목 위치
- 기타 Debug 정보

---

# 10. 경로 표시 정책

모든 로봇의 전체 경로를 항상 표시하면 미니맵이 복잡해질 수 있다.

따라서 다음 방식이 적절하다.

### 기본

```text
현재 위치 + 방향
```

### 로봇 선택

```text
현재 위치 + 방향 + 선택 로봇 경로
```

### 경로 토글 ON

```text
모든 로봇 경로
```

이 방식은 기존 시스템의 로봇별 경로선 On/Off 기능과도 자연스럽게 연결할 수 있다.

---

# 11. 미니맵과 히트맵의 역할 분리

미니맵과 히트맵은 하나로 합치지 않는 것을 권장한다.

## 미니맵

> 지금 어디에 있는가?

표시:

- 창고 구조
- 로봇 위치
- 로봇 방향
- 선택 로봇 경로

## 히트맵

> 어디가 병목인가?

표시:

- 대기량
- 통과량
- 병목 위치
- 혼잡도

즉:

```text
MINIMAP
────────────
현재 상황 파악


HEATMAP
────────────
분석 및 병목 파악
```

---

# 12. 재생 중 미니맵 확대

시뮬레이션 재생 중에는 미니맵을 약간 확대하는 방식을 고려한다.

### 평상시

```text
┌────────────┐
│  MINIMAP   │
│            │
│    ●       │
└────────────┘
```

### 재생 중

```text
┌────────────────┐
│    MINIMAP     │
│                │
│  ● →      ●    │
│       ●        │
│  ●             │
└────────────────┘
```

목적은 사용자가 3D 창고를 직접 보면서도 전체적인 로봇 움직임을 쉽게 파악하도록 하는 것이다.

단, 실제 크기와 확대 정도는 Quest 2에서 사용성 테스트를 통해 결정한다.

# 13. 미니맵 인터랙션

미니맵을 단순한 정보 표시 영역이 아니라 보조 조작 영역으로 사용할 수 있다.

```text
미니맵
   │
   ├── 로봇 클릭
   │       ↓
   │    로봇 선택
   │
   ├── 위치 클릭
   │       ↓
   │    해당 위치 Focus
   │
   └── 확대 버튼
           ↓
        전체 맵 보기
```

### 로봇 클릭

```text
미니맵에서 R1 선택
       ↓
3D에서 R1 Focus
       ↓
R1 경로 표시
```

### 위치 클릭

```text
미니맵 위치 선택
       ↓
3D Camera 이동
       ↓
해당 위치 강조
```

# 14. 병목 분석과 미니맵 연결

미니맵을 분석 기능과 연결할 수 있다.

```text
히트맵
  ↓
진한 영역 클릭
  ↓
해당 위치 선택
  ↓
3D Camera Focus
  ↓
해당 위치의 대기/통과 정보 표시
```

예:

```text
bottleneck (12,8)
     ↓
3D Focus
     ↓
"이 위치에서 대기 32회"
```

다만 병목 데이터 자체를 미니맵 기본 상태에서 항상 표시하기보다는 분석/토글 기능으로 제공하는 것이 좋다.

# 16. 사용자 경험 관점의 장점

이 기능은 단순한 장식용 미니맵이 아니다.

사용자가:

1. 3D 창고의 실제 공간을 확인하고
2. 미니맵으로 전체 창고를 조망하고
3. 로봇들의 위치와 방향을 확인하고
4. 실행 중 전체적인 이동 흐름을 파악하고
5. 필요하면 특정 로봇 또는 위치를 선택해 자세히 보는

흐름을 만들 수 있다.

즉:

```text
3D 상세 관찰
      +
미니맵 전체 조망
      ↓
전체 상황 이해
```

라는 역할 분담이 된다.

# 17. 기존 시스템과의 연결

현재 시뮬레이션 구조가 다음과 같은 형태라면:

```text
sim_ready
    ↓
프레임 요청
    ↓
{t, robots:[id,x,y,state]}
    ↓
VR 이동 재생
```

미니맵은 기존 프레임 데이터를 그대로 재사용한다.

```text
                Frame Data
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
    3D Robot View        Minimap View
          │                   │
          └─────────┬─────────┘
                    ↓
              동일 시간축
```

따라서 미니맵 추가를 위해 별도의 시뮬레이션 계산을 만들 필요 없이 **기존 시뮬레이션 데이터를 시각화하는 구조**로 구현하는 것이 좋다.

# 18. 최종 권장안

### 상태별

| 상태 | 미니맵 |
|---|---|
| 맵 생성 전 | 숨김 |
| 맵 생성 완료 | 창고 구조 표시 |
| Simulation Ready | 로봇 위치 표시 |
| Running | 로봇 위치/방향 실시간 이동 |
| Paused | 현재 위치에서 정지 |
| Completed | 최종 위치 유지 + 결과 요약 |

### 기본 정보

```text
창고 구조
+
로봇 위치
+
로봇 방향
```

### 선택 기능

```text
로봇 선택
경로 표시
3D Focus
위치 Focus
확대
히트맵/병목 연동
```

# 19. 결론

**맵 생성 이후 미니맵을 표시하고, 시뮬레이션 실행 중 로봇이 미니맵에서 실제 움직임과 동기화되어 움직이도록 하는 방향을 권장한다.**

특히 현재 프로젝트의 핵심 시연 흐름인:

```text
Agent가 창고 생성
      ↓
맵 생성
      ↓
시뮬레이션
      ↓
로봇 이동
```

을 사용자가 한 화면에서 이해하기 쉬워진다는 장점이 있다.

따라서 미니맵은 단순 장식 요소가 아니라 **3D 상세 화면과 전체 상황 파악을 연결하는 핵심 보조 UI**로 설계하는 것이 적절하다.

# 20. 다음 구현 단계

미니맵 설계가 확정되면 다음 단계에서 실제 Unity 구현 기준으로 구체화할 수 있다.

```text
Minimap
│
├── MinimapCanvas
│
├── MapRenderer
│   └── Grid / Wall / Dock
│
├── RobotMarkers
│   ├── RobotMarker_R1
│   ├── RobotMarker_R2
│   ├── RobotMarker_R3
│   └── RobotMarker_R4
│
├── PathRenderer
│
├── Selection
│
├── FocusButton
│
└── ExpandButton
```

그리고 데이터 흐름은:

```text
Simulation Frame
      ↓
MinimapController
      ├── UpdateMap()
      ├── UpdateRobot()
      ├── UpdateDirection()
      ├── UpdatePath()
      └── UpdateSelection()
```

형태로 내려가면 실제 Unity 구현으로 바로 연결할 수 있다.
