# E2E 필수 시연 케이스

| 항목 | 내용 |
|---|---|
| 근거 문서 | 통합 테스트 케이스 v0.1, 구현 시나리오 v0.1(E2E·7장 시연 시나리오), 대회 공고문 |
| 팀 | 로봇웨어하우스 (방유진 · 백향 · 하재윤) |
| 문서 버전 | v0.1 (2026-09-30 초안) |
| 사용 시점 | 10/2 E2E 마일스톤, 10/5 영상 촬영, 10/12 발표·시연 심사 |

**왜 따로 두는가**

공고문은 "기능 수보다 AI Agent다운 문제 해결 과정과 실제 동작 여부"를 먼저 평가하고, 유효 제출작은 최소 1개 End-to-End Workflow가 동작해야 합니다. 이 문서는 심사에서 **반드시 성공해야 하는 흐름**만 모아, 리허설과 촬영 때 그대로 따라 하도록 만든 실행 대본입니다.

**구분**

| 구분 | 의미 | 실패 시 |
|---|---|---|
| **필수 (M)** | 이것이 안 되면 Level 3(MVP) 주장 불가 | 새 기능 개발을 멈추고 이것부터 복구 |
| **권장 (R)** | 되면 시연에 넣어 경쟁력을 높임 | 시연 순서에서 빼고 진행 |

## 0. 전체 합격 기준

- [ ] 필수 케이스 M01~M05가 **사람 손 개입 없이**(서버 재시작, 파일 수동 복사, 코드 수정 없음) 성공
- [ ] 연속 흐름 M04를 **3회 연속** 성공
- [ ] 화면에서 **입력 → Agent 판단 → 도구 실행 → 결과**가 모두 보임 (공고문 시연영상 기준)
- [ ] 시연 전체가 **3분 안**에 끝남
- [ ] 충돌 검사 0건이 서버 로그로 확인됨

## 2. 필수 케이스 (M)

### E2E-M01 음성으로 창고 만들기

| 항목 | 내용 |
|---|---|
| 심사에서 보여 줄 것 | 경로 계획 지식 없이 **말로** 창고를 만든다 |
| 관련 | SC-02 → SC-01 · FR-02, 03, 04, 06, 07, 20 · ITC-03, 04, 26, 27 |
| 사전 상태 | 앱 연결됨, 빈 공간 |
| 시연 동작 | 녹음 버튼을 누르고 말한다: **"랙 8줄, 통로 폭 3미터, 입하 도크 2개, 출하 도크 1개, 충전 구역은 오른쪽 벽 쪽에"** |
| 기대 화면 | ① 패널에 인식 문장 → ② "창고 생성 중" → ③ 3D 창고 생성, 요약 표시 → ④ "확인" 버튼 활성 |
| 서버 로그 | `transcript` → `interpret` → `generate_map` → `validate(valid=true)` → `map_ready` |
| 합격 기준 | 랙 8줄, 입하 2·출하 1이 VR에 보임 / 발화 끝부터 창고 표시까지 `[ ]`초 이내 |
| 목표 시간 | 30초 |
| 실패 시 | 인식 실패 → 한 번 더 말함 / 두 번 실패 → 입력 패널에 텍스트로 입력 (같은 문장 미리 복사해 둠) |

### E2E-M02 Agent가 문제를 찾아 되묻기

| 항목 | 내용 |
|---|---|
| 심사에서 보여 줄 것 | LLM 결과를 그대로 믿지 않고 **검증 → 질문 → 재생성**하는 Agent 판단 과정 |
| 관련 | SC-03 · FR-06~08 · ITC-09, 12 |
| 사전 상태 | M01 창고가 떠 있음 (또는 새 입력) |
| 시연 동작 | 말한다: **"랙 6줄, 통로 폭 3미터"** (도크 정보 없음) → 질문이 나오면: **"입하 도크 1개 왼쪽 벽, 출하 도크 1개 오른쪽 벽"** |
| 기대 화면 | ① 패널에 질문 "입하 도크는 몇 개, 어느 벽에 둘까요?" → ② 답변 인식 → ③ 도크가 포함된 창고로 다시 생성 |
| 서버 로그 | `validate(valid=false, NO_DOCK_IN, NO_DOCK_OUT)` → `question` → `answer` → `validate(valid=true)` |
| 합격 기준 | 질문이 오류 원인(도크 없음)을 말함 / 답변 뒤 검증 통과 |
| 목표 시간 | 30초 |
| 실패 시 | 질문 문구가 이상하면 그대로 답하고 진행 / 재생성 실패 → M01 창고로 돌아가 M03 진행 |
| 대안 입력 | "랙 10줄을 통로 없이 붙여서" → 도달 불가 질문 → "통로 3미터로" |

### E2E-M03 다중 로봇 경로 계산과 VR 재생

| 항목 | 내용 |
|---|---|
| 심사에서 보여 줄 것 | 여러 로봇이 **충돌 없이** 동시에 움직이는 계산 결과를 VR로 본다 |
| 관련 | SC-04, 05 · FR-11, 12, 14~16, 21, 22 · ITC-05, 06, 17 |
| 사전 상태 | W2 창고 생성됨 |
| 시연 동작 | "확인" → 시나리오 패널에 로봇 4대, 입하 25, 출하 25 → "실행" → 재생 → 배속 4x |
| 기대 화면 | ① 로봇 큐브 4대가 도크와 랙 사이를 오감 ② 상태별 색(이동·적재·대기) ③ 배속 변경이 바로 반영 ④ 재생 끝에 총 스텝·완료 주문 수 |
| 서버 로그 | `simulate(strategy=optimized)` → `collisions=0` → `sim_ready` |
| 합격 기준 | 완료 주문 50/50 / 충돌 0 / 재생 중 로봇이 겹치거나 순간이동하지 않음 |
| 목표 시간 | 40초 (배속 사용) |
| 실패 시 | 계산이 늦으면 S1(로봇 2대, 주문 20)로 줄임 / 네트워크 문제 → 오프라인 재생 |

### E2E-M04 연속 흐름 (시연 최소 시나리오)

| 항목 | 내용 |
|---|---|
| 심사에서 보여 줄 것 | **하나의 End-to-End Workflow**가 끊김 없이 동작 |
| 관련 | 구현 시나리오 E2E · TC-E2E-01, 02 · ITC-33 |
| 절차 | 앱 시작 → M01 → 확인 → M03 (S2) → 재생 완료 |
| 합격 기준 | **3회 연속** 성공, 매회 서버·앱 재시작 없음 / 1회당 `[ ]`분 이내 |
| 기록 | 회차별 소요 시간, 실패 지점 (6장 기록표) |
| 비고 | 성공한 회차는 그 자리에서 바로 백업 영상으로 녹화 (다시 재현하려다 실패할 수 있음) |

### E2E-M05 구조가 다른 창고에서도 동작

| 항목 | 내용 |
|---|---|
| 심사에서 보여 줄 것 | 창고 크기·구조가 달라도 같은 흐름이 동작 (범용성) |
| 관련 | NFR-09 · TC-E2E-03 |
| 시연 동작 | 말한다: **"랙 6줄을 좌우 두 구역으로 나누고, 가운데 큰 통로는 북쪽 방향 일방통행"** → 확인 → 로봇 4대, 입하 25, 출하 25 → 재생 |
| 합격 기준 | 두 구역 구조 생성 / 가운데 통로에서 남쪽으로 이동하는 로봇 없음 / 충돌 0 |
| 목표 시간 | 발표 시간이 부족하면 영상에서 10초 장면으로 대체 |
| 실패 시 | 일방통행 규칙이 미구현이면 "랙 4줄, 입하 1, 출하 1"(W1)로 바꿔 크기만 다른 창고를 보여 줌 |

## 3. 권장 케이스 (R)

> 구현 상태에 따라 시연 순서에 넣습니다. 10/4 기능 동결 때 포함 여부를 확정합니다.

### E2E-R01 혼잡 구간 히트맵

| 항목 | 내용 |
|---|---|
| 보여 줄 것 | 수치표 대신 바닥 색으로 혼잡 구간을 **바로** 찾는다 |
| 관련 | SC-06 · FR-23, 24 · ITC-08 |
| 시연 동작 | 로봇 8대(S2-H)로 재실행 → "히트맵" 켬 → 로봇 1대 선택 후 "경로 선" 켬 |
| 합격 기준 | 도크 앞·교차 통로가 진하게 표시 / 선택 로봇 경로만 선으로 표시 / FPS 저하로 재생이 끊기지 않음 |
| 목표 시간 | 20초 |
| 실패 시 | 8대에서 프레임이 떨어지면 6대로 줄임 |

### E2E-R02 기준 전략과 비교

| 항목 | 내용 |
|---|---|
| 보여 줄 것 | 최적화 전략이 기준 전략보다 얼마나 빠른지 **수치로** |
| 관련 | SC-07 · FR-18, 28 · ITC-19 |
| 시연 동작 | 결과 패널의 "기준 전략과 비교" |
| 합격 기준 | 두 처리 시간과 개선율 표시, 보고서·발표자료의 수치와 같음 |
| 목표 시간 | 15초 |

### E2E-R03 병목 원인 설명

| 항목 | 내용 |
|---|---|
| 보여 줄 것 | Agent가 로그 수치를 근거로 병목 원인과 개선 방향을 **설명** |
| 관련 | SC-09 · FR-26, 27 · ITC-22 |
| 시연 동작 | S2-H 결과에서 말한다: **"어디가 막혀?"** |
| 기대 화면 | 병목 칸 마커 + 설명 (예: "출하 도크 앞 (12, 3) 칸에서 대기 `[ ]`회, 로봇이 한 통로로 몰립니다") + 개선안 버튼 1~3개 |
| 합격 기준 | 설명에 좌표나 수치가 1개 이상 / 마커 위치가 히트맵 진한 칸과 같음 |
| 목표 시간 | 25초 |

### E2E-R04 개선안 적용 후 재시뮬레이션

| 항목 | 내용 |
|---|---|
| 보여 줄 것 | 사용자 **승인** 뒤에만 개선안을 적용하고 전·후를 비교 |
| 관련 | SC-10 · FR-29 · ITC-23, 24 |
| 시연 동작 | R03의 개선안 하나 선택 → "적용" |
| 합격 기준 | 적용 전·후 처리 시간과 히트맵 비교 표시 |
| 목표 시간 | 25초 |
| 비고 | P2. 미구현이면 R02 비교로 대신 마무리 |

### E2E-R05 재생 중 주문 추가 (롤링 재계획)

| 항목 | 내용 |
|---|---|
| 보여 줄 것 | 물량·로봇 수가 바뀌면 진행 중인 계획을 다시 계산 |
| 관련 | SC-08 · FR-19 · ITC-20 |
| 시연 동작 | 재생 중 "주문 10건 추가" + 로봇 6대로 변경 |
| 합격 기준 | 로봇이 늘어나고 재생이 끊기지 않음, 추가 주문 완료 |
| 목표 시간 | 20초 |
| 비고 | 3분 영상에는 시간이 부족하면 넣지 않고 발표 질의응답용으로 준비 |

## 4. 3분 연속 시연 대본

> 시연영상과 발표 시연에 같은 순서를 씁니다. 괄호 안은 해당 케이스입니다.

| 시간 | 장면 | 화면 | 발표자 말 (요약) |
|---|---|---|---|
| 0:00–0:15 | 문제 제시 | 제목 카드 | "로봇 여러 대가 좁은 통로를 함께 쓰면 최단 경로만으로는 느려집니다. 이걸 도입 전에 확인해 보겠습니다." |
| 0:15–0:45 | 말로 창고 만들기 (M01) | VR + 서버 로그 | "창고를 말로 설명하면 Agent가 격자 지도를 만들고 검증합니다." |
| 0:45–1:10 | Agent가 되묻기 (M02) | 질문 패널, 로그의 `validate=false` | "도크 정보가 빠지면 Agent가 스스로 찾아내 되묻습니다." |
| 1:10–1:45 | 다중 로봇 재생 (M03, S2-H) | 로봇 8대, 배속 4x | "주문과 로봇 상태를 보고 작업을 나누고, 충돌 없이 경로를 계산했습니다." |
| 1:45–2:05 | 히트맵 (R01) | 바닥 색 | "혼잡한 구간이 바닥 색으로 바로 보입니다." |
| 2:05–2:30 | 병목 설명 (R03) | 마커 + 설명 | "어디가 막히는지 물으면 로그 수치를 근거로 원인을 설명합니다." |
| 2:30–2:50 | 비교 (R04 또는 R02) | 전·후 수치 | "기준 전략 대비 처리 시간 `[ ]`% 단축." |
| 2:50–3:00 | 마무리 | 구조도 | "말로 짓고, VR로 확인하고, Agent가 개선합니다." |

**권장 케이스가 빠질 때 줄인 대본:** M01(30초) → M02(25초) → M03(40초) → 결과 요약·구조도(25초) = 약 2분

## 5. 실패 대응표

| 상황 | 신호 | 대응 | 담당 |
|---|---|---|---|
| 음성 인식 실패 | 패널에 인식 문장이 비거나 틀림 | 한 번 더 말함 → 두 번째 실패 시 텍스트 입력 | 백향(VR 조작) |
| LLM 응답 지연 | "생성 중"이 `[ ]`초 넘게 지속 | 재시도 버튼 1회 → 실패 시 W2 저장 지도 불러오기 | 방유진(서버) |
| 서버 연결 끊김 | "재연결 중" 표시 | 10초 대기 → 복구 안 되면 오프라인 재생 | 방유진 |
| Wi-Fi 없음·불안정 | 연결 실패 | 휴대폰 핫스팟으로 전환(IP 재입력) → 안 되면 오프라인 재생 | 백향 |
| 재생 프레임 저하 | 로봇 움직임이 끊김 | 로봇 수를 줄여 재실행, 히트맵 끔 | 하재윤(시나리오 조정) |
| Quest 2 문제 | 화면 멈춤, 배터리 | 예비 Quest 2로 교체 → 불가 시 백업 영상 재생 | 백향 |
