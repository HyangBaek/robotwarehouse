# 프로젝트 회고 및 개선방안

| 항목 | 내용 |
|---|---|
| 과제명 | 말로 짓고 로봇이 달리는 무인 물류창고 |
| 대회 | 제4회 경남 AI·SW 경진대회 · 3-2. MetaQuest2 VR 기반 피지컬 AI Agent |
| 팀 | 로봇웨어하우스 (방유진 · 백향 · 하재윤) |
| 개발 기간 | 2026-09-29 ~ 10-06 (8일) |
| 문서 버전 | v0.1 (양식) |

**작성 일정**

| 시점 | 작성 내용 | 방식 |
|---|---|---|
| 10/6(화) 제출 직후 ~ 10/7(수) | 1장 결과 요약, 2장 개인 평가 | 각자 작성 |
| 10/7(수) | 3~5장 팀 회고, 문제 분석, 개선방안 | 팀 회의 1시간 |
| 10/12(월) 발표 후 | 6장 심사 질문·피드백 | 발표 직후 바로 기록 |
| 10/14(수) 시상 후 | 6장 결과, 8장 향후 계획 확정 | 팀 회의 30분 |

**작성 원칙**
- 느낌보다 사실을 먼저 씁니다. "시간이 부족했다"보다 "10/2 E2E가 10/3 오후로 하루 밀렸다"가 개선방안을 만들기 쉽습니다.
- 문제는 사람이 아니라 과정에서 찾습니다. "누가 늦었다" 대신 "스키마 변경이 공유되지 않아 VR과 서버가 다른 필드를 썼다"처럼 씁니다.
- 개선방안에는 담당자와 기한을 붙입니다. 붙일 수 없으면 개선방안이 아니라 소감입니다.
