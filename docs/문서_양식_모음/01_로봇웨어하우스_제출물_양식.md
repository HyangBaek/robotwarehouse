### 1. 개요

**1.1 문제 정의**

> 신청서 "목적"을 줄여 쓰고, 이 문제가 왜 어려운지를 한 문단으로 정리합니다.

로봇과 무인 지게차만으로 운영되는 자동화 물류창고에서는 여러 대의 로봇이 좁은 통로를 함께 쓰기 때문에, 로봇 한 대의 최단 경로보다 전체 로봇의 동선 조율이 처리 속도를 좌우한다. 입출하 물량이나 가동 로봇 수가 바뀌면 병목 위치도 달라진다. 그러나 이를 도입 전에 검토하려면 창고 도면을 시뮬레이터용으로 옮기는 작업과 경로 계획 전문 지식이 필요해, 중소 물류·제조 기업이 직접 시도하기 어렵다.

**1.2 대상 사용자와 사용 상황**

| 항목 | 내용 |
|---|---|
| 주 사용자 | 자동화 창고 도입을 검토하는 중소 물류·제조 기업의 운영·기획 담당자 |
| 사용 상황 | 로봇 대수, 랙 배치, 물동량을 바꿔 가며 처리 시간과 병목을 도입 전에 비교 |
| 사용자가 가진 것 | 창고 구조에 대한 말로 된 설명, 예상 물동량 |
| 사용자에게 없는 것 | 시뮬레이터 모델링 능력, 다중 로봇 경로 계획 지식 |

**1.3 목표와 달성 수준**

- 목표 완성도: Level 3(MVP) — 최소 1개 End-to-End Workflow 안정 동작

### 2. AI Agent 구조

**2.1 전체 구조도**

> 그림 1장으로 넣습니다. 아래는 그림을 그릴 때 참고할 텍스트 구조입니다.

```
[사용자 · Quest2]
   │ 음성/텍스트 입력, 랙 수동 배치
   ▼
[VR 클라이언트 · Unity/C#] ──────────────┐
   │ REST/WebSocket                       │ 시간 단계별 로봇 위치, 칸별 통과·대기 집계
   ▼                                      │
[에이전트 서버 · FastAPI + LangGraph]      │
   ├─ 지시 해석 (LLM)                      │
   ├─ 격자 지도 생성 도구                   │
   ├─ 지도 검증 도구 → 실패 시 수정 질문     │
   ├─ 시뮬레이션 실행 도구 ──▶ [경로 계산 서버 · Python]
   ├─ 로그 집계 도구                        (작업 할당, 다중 로봇 경로, 충돌 검사)
   └─ 분석·개선안 제안 (LLM)
```

**2.2 Agent 워크플로우**

| 단계 | 노드 | 입력 | 판단 주체 | 출력 |
|:-:|---|---|---|---|
| 1 | 지시 해석 | 음성(Whisper)·텍스트 | LLM | 창고 구성 요구사항 |
| 2 | 격자 지도 생성 | 요구사항 | 도구 | 격자 지도 JSON |
| 3 | 검증·수정 질문 | 격자 지도 | 검증 도구 + LLM | 통과 / 수정 질문 |
| 4 | 시뮬레이션 실행 | 지도 + 주문 + 로봇 수 | 경로 계산 서버 | 이동 로그 |
| 5 | 로그 분석 | 이동 로그 | 집계 도구 + LLM | 혼잡도, 병목 |
| 6 | 개선안 제안 | 분석 결과 | LLM → 사용자 승인 | 개선안, 재시뮬레이션 |

**2.3 설계 원칙**

- 계산과 판단의 분리: 경로 계산은 검증된 알고리즘이 맡고, LLM은 구조 해석, 도구 실행 순서 결정, 결과 해석과 개선안 제시를 맡는다.
- 승인 후 반영: LLM이 만든 격자 지도와 개선안은 검증 도구와 사용자 승인을 거친 뒤에만 반영한다.
- 단일 데이터 형식: 격자 지도 스키마 하나로 VR, 알고리즘, 에이전트가 같은 데이터를 쓴다.

> 공고문 기준: 편집된 홍보 영상보다 실제 입력 → 판단 → 도구 실행 → 결과가 보여야 합니다.

| 7 | 주요 구현 ② 다중 로봇 경로·VR | 작업 할당, 충돌 회피 경로, Quest2 재생, 히트맵 | VR 캡처 2장 |

| 10 | 한계와 발전 계획 | 가정(완전 무인, 격자 단위 시간), 혼재 운영·CAD 입력·다층 랙, 지역 연계 | 로드맵 |

**예상 질문 준비**
- LLM이 잘못된 지도를 만들면? → 검증 도구와 사용자 승인을 거친 뒤에만 반영
- 기존 시뮬레이터와 무엇이 다른가? → 모델링을 말로 대체, 분석 결과를 에이전트가 설명
- 처리 시간이 실제와 다르지 않나? → 격자 단위 시뮬레이션 값이며 상대 비교 용도임을 한계로 명시
- 신규 개발분은? → 스키마, 창고 구성 에이전트, VR 앱, 경로 연계·비교 실험 (알고리즘은 공개 논문 참고)
